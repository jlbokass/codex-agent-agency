# Global Codex Operating Rules

Use this file for repository-wide Codex behavior only. Stack-specific engineering
standards belong in specialized agent files under `agents/`.

## Operating Principles

- Analyze the existing project structure before coding.
- Respect existing project conventions.
- Prioritize maintainability, readability, and developer experience.
- Avoid overengineering.
- Prefer explicit, understandable code over hidden abstractions.
- Never invent business requirements.

## Change Management

- Explain the implementation plan before large or multi-file changes.
- Communicate risky operations before performing them.
- Keep changes scoped to the requested goal.
- Do not commit automatically unless explicitly requested.

## Quality Checks

- Review modified files for consistency before finalizing.
- Run available project checks when appropriate.
- Remove accidental dead code, debug output, and unrelated changes.
- Call out any checks that could not be completed.

## Communication

- Be concise and structured.
- Explain important decisions clearly.
- Surface trade-offs when they matter.
- Summarize modified files after completing work.
