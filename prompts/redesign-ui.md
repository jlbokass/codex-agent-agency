# Prompt — Redesign UI

Use this prompt when redesigning a page, section, component, landing page, form, dashboard, or full interface.

## Prompt

Using the active project instructions, specialized agents, workflows, checklists, and design-system files when available, help me redesign the following UI:

[DESCRIBE THE PAGE / SECTION / COMPONENT HERE]

Follow the active UI Redesign Workflow.

Before modifying files:

1. Read the project `AGENTS.md`.
2. Inspect the existing repository structure.
3. Inspect the relevant templates, styles, scripts, components, and assets.
4. Identify the current UI structure.
5. Identify the target users and business goal.
6. Identify the primary CTA and secondary actions.
7. Identify UX friction points.
8. Identify responsive constraints.
9. Identify accessibility risks.
10. Identify technical constraints.

Do not modify files yet.

First provide a UI/UX redesign plan including:

- current UI diagnosis
- user goal
- business goal
- UX strategy
- primary CTA hierarchy
- visual direction
- layout strategy
- responsive strategy
- accessibility considerations
- files likely to change
- implementation risks

The proposed design must avoid:

- generic Bootstrap appearance
- repetitive card grids
- predictable AI-generated sections
- weak typography hierarchy
- flat spacing
- template feeling
- decorative elements without UX purpose

The proposed design should prioritize:

- premium visual quality
- strong hierarchy
- editorial layout
- visual rhythm
- responsive polish
- accessibility basics
- clear conversion path
- distinctive art direction

Wait for confirmation before implementing.

After confirmation:

1. Implement incrementally.
2. Preserve existing architecture.
3. Keep templates readable.
4. Keep business logic out of templates.
5. Keep CSS organized.
6. Avoid unnecessary dependencies.
7. Ensure responsive behavior.
8. Ensure accessibility basics.
9. Run relevant checks when available.
10. Apply the UI/UX Quality Gate checklist.
11. Apply the Definition of Done checklist.
12. Apply the Release Readiness checklist if delivery-ready.

Final response must include:

- design intent
- UX choices
- visual direction
- files modified
- responsive decisions
- accessibility notes
- commands run
- checks passed
- checks not run and why
- remaining risks
- suggested commit message
